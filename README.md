## 一、 为什么国内本地直连跑 CC 必踩坑？

我之前也是在自己日常办公的 MacBook 上开代理跑 `claude`，踩过三个最致命的工程坑：

1. **风控封号防不胜防：** 国内节点线路今天美西、明天日本，再加上万人骑的数据中心 ASN 污染、虚拟卡拒付追溯，Anthropic 现在的风控模型直接判定异常，触发无法通过的美区 KYC 审核，号说没就没。
2. **合盖即断，长任务根本跑不完：** 让 CC 跨几十个文件做重构或跑全套单测，经常要跑一两个小时。笔记本一合盖休眠或者切个 Wi-Fi，SSH 和终端会话直接断开，上下文全丢。
3. **高权限 Agent 放本地心里发毛：** 想要它真正自动化改代码、跑测试，必须放开终端执行权限。在存满自己私钥、公司源码和个人资料的主力机上开全权限风险太大。

想通之后我的做法很彻底：**国内电脑只留着当显示器和键盘，所有代码仓库、运行环境和 Claude Code 全部放到美西的独立物理 Mac mini 上跑，国内任何流量绝不直接暴露给 Anthropic。**

## 二、 我交了学费总结的 2026 防封铁律

今年 Anthropic 的风控已经从单纯查 IP 升级成对**网络 ASN、支付卡属性、设备指纹和调用节奏**的综合打分。结合我被封号和后来稳如老狗的对比经验，这几条底线一定要守住：

* **一机一号，物理隔离：** 商业共享节点和多人拼车（多 IP、多指纹并发）基本是秒封重灾区。最稳的架构就是**一人一台海外物理机 + 一个独立账号**，所有操作全在远程 Mac 里完成，绝不在国内本地电脑上混登。
* **支付必须干净：** 各类虚拟卡现在基本被 Stripe 批量拒付拉黑了，连带封号率极高。自己搭的话，**务必找非风险区域的真实个人实体信用卡订阅**，并确保账单地址和你的远程机器所在地区一致。
* **远离低价成品号：** 某宝闲鱼上那种百来块钱的成品号大概率是黑卡代充，过一两个月银行撤单直接连坐封号。真要找人代订阅，**只找信得过的熟人渠道或靠谱的正规服务商**。
* **新号前 72 小时忍住别狂飙：** 刚注册订阅的前三天是风控观察期，按正常码农写代码的节奏每天聊十几轮就行，千万别一上来就通宵挂脚本批跑。
* **脚本必须带熔断：** 挂机最怕网络抽风或者报错时死循环高频重试，直接触发自动化爬虫封禁。所以我下面的守护脚本专门写了**连续快速崩溃熔断保护**。

## 三、 实战部署：用我写的脚本一键体检与保活

如果你自己已经在海外买好了 macOS 机器，按下面几步就能把无人值守环境搭起来：

### 1. Tailscale 私有内网穿透
不建议把远程 Mac 的 SSH 端口直接暴露在公网上，用 Tailscale 组个点对点加密内网最安全，国内直连延迟也很低：

```bash
brew install --cask tailscale
# 安装后登录你的 Tailscale 账号完成设备授权
# 之后无论在公司还是家里，直接通过分配的内网 IP（100.x.x.x）连 SSH 或屏幕共享（VNC）
```

### 2. 运行 `setup.sh` 做出口 IP 与时区审计
每次拿到新机器或调整网络后，我都会先跑一遍这个脚本。它会用 macOS 原生解析检查当前出口 IP 的 ASN 归属，并对比**本机系统时区和 IP 所在时区是否一致**（时区对不上也是高频风控点），顺便把 `tmux`、`Node.js` 和 `claude` 补齐：

```bash
git clone https://github.com && cd awesome-claude-code-remote
bash setup.sh
```

### 3. 运行 `watchdog.sh` 挂起无人值守任务
这是我自用的防断线保活脚本：调用 `caffeinate -disu` 锁死系统防止休眠；把进程丢进 `tmux` 后台；如果遇到网络波动异常退出（非 `0` 且非手动 `Ctrl+C` 的 `130` 退出码），等待 20 秒后自动用 `--continue` 续跑；**如果 15 秒内连续崩溃 3 次，自动触发安全熔断停止拉起，保护账号安全**。

```bash
# 模式 A：启动交互式保活会话（防合盖断连）
bash watchdog.sh ~/projects/your-repo claude-work

# 模式 B：睡前丢一个任务清单让它自己跑（支持直接传 @TASK.md 文件，跑完自动退出循环）
bash watchdog.sh ~/projects/your-repo claude-batch @TASK.md
```

**日常接管后台的常用快捷键：**
* **暂离终端（让任务继续在后台跑）：** 先按 `Ctrl + B`，松开后再按 `D`。然后你就可以直接关电脑睡觉了。
* **随时连回去看进度：** `tmux attach -t claude-work`
* **看守护进程有没有触发熔断：** `tail -f ~/.claude/logs/watchdog_claude-work.log`

### 4. 避坑：无人值守时的权限卡死问题
用过 CC 的同行都知道，默认安全模式下它每次改文件或执行测试命令都会停下来等人工敲 `Yes` 确认。半夜挂机没配置好权限，它会在第一步就卡死到天亮。

有两种解决办法：
1. **配安全白名单（推荐）：** 在项目根目录的 `.claude/settings.local.json` 里预先把 `Bash(npm test:*)`、`Edit` 等常用工具放行。
2. **隔离环境全权限模式：** 因为我的代码跑在**美西完全隔离的独立物理 Mac mini** 上，里面没有任何国内个人隐私文件，所以我跑通宵重构时习惯直接加 `--dangerously-skip-permissions` 参数：
   ```bash
   claude --dangerously-skip-permissions -p "阅读 TASK.md，完成核心模块开发并跑通所有单测，测试通过后提交一个 Git Commit。"
   ```

## 四、 日常排错常用命令

后台跑任务偶尔遇到网络瞬断或认证过期，用这几个原生命令排查最快：

```bash
# 排查认证状态、配置文件语法和环境异常
claude doctor

# 恢复当前目录最近一次中断的会话上下文
claude --continue

# 列出历史会话列表，手动挑一个时间点恢复
claude --resume
```

## 五、 常见疑问（FAQ）

**Q：国内这样远程用 Claude Code 合规吗？怎么避坑？**
> 用官方 CLI 写代码本身就是正常的开发工具需求，真正导致封号的是黑卡代充、共享节点或者多人拼车倒卖。**如果你对自己的网络配置、订阅方式或者隔离环境搭法拿不准，欢迎直接加我微信聊，我按我踩过的坑帮你看看。**

**Q：一个账号能在手机和电脑上同时登录吗？**
> 官方允许同一账号在不同设备上切换登录，但**千万别多端同时并发发请求**（比如远程机器在狂跑代码，你本地浏览器同时也在刷对话），这会直接被风控系统判定为账号共享或脚本滥用。

**Q：触发了美区 KYC 身份验证还能申诉回来吗？**
> 别抱太大希望，我自己和身边朋友试过好几次，没有美区本土身份和地址证明基本申诉不回来。所以前期把物理和网络环境隔离开，比事后补救靠谱得多。
